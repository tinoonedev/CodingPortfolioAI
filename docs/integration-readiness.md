# Integration readiness contract

This document defines the minimum production contract for connecting Fieldwork to external services. It is a design baseline, not evidence that a connector is implemented. The current app has no live Jira, Figma, GitHub, OpenAI, or deployment integration; do not report an external action as complete unless the service confirms it.

Before implementation, assign a named product owner and technical owner, confirm the target account/project/repository, verify each permission against the exact API endpoint, and record the credential owner and rotation process. Keep credentials server-side in a managed secret store. Never place tokens in browser storage, source control, prompts, or logs.

| System | Identity and minimum access | Human ownership and target confirmation | Audit evidence | Failure and retry behavior |
| --- | --- | --- | --- | --- |
| Jira Cloud | OAuth 2.0 (3LO); request only endpoint-required scopes. Likely baseline: `read:jira-work`, `write:jira-work`; use `read:jira-user` only when account identity is needed for the approval gate. | Jira administrator owns app registration and callback URI. A human selects/approves the site and project. Validate confirmation comments against the allowed Jira account and exact issue/revision. | Site, issue key, actor, operation, comment/transition identifiers, approval revision, request correlation ID, timestamp, and outcome. | Treat 401/403 as a connection or permission failure; do not retry. Honor 429 `Retry-After`; use bounded exponential backoff for transient network/5xx errors. Make writes idempotent where API semantics allow and re-read state after ambiguous timeouts. |
| Figma | OAuth with granular, endpoint-specific scopes. Request `file_content:read` and `file_metadata:read` only when needed; request `file_comments:read`/`file_comments:write` only for comment features. | Figma administrator owns app registration and fixed redirect URI. A human selects the team/file and confirms design handoff. | Figma user, team/file key, requested artifact or comment IDs, operation, timestamp, and outcome. | Do not treat inaccessible files as empty designs. Surface permission/plan/rate-limit failures; retry only transient errors with bounded backoff and re-check before repeating writes. |
| GitHub | Prefer a GitHub App installed only on selected repositories. Start with metadata read; grant contents write and pull request write only for branch/commit/PR operations. Add checks or deployment permissions only when their feature is implemented. | Repository/org owner approves installation and selected repositories. A human confirms the repository, base branch, and production deployment target. | Installation/repository, actor, branch, commit SHA, PR number, workflow run, deployment environment, and operation outcome. | Use short-lived installation tokens. Do not request organization administration or workflow-file write without a separate documented need and approval. Reconcile uncertain create operations by searching for the branch/PR before retrying. |
| OpenAI API | Project-scoped API key, restricted to the server-side runtime. Maintain an explicit model allowlist, per-project budget, and rate limits. | OpenAI project owner manages key creation, rotation, spend limits, and access. A human approves the project’s model and data-handling policy. | Request ID, project, model, timestamps, token/cost usage when available, and outcome; redact prompts and sensitive content from routine logs. | Handle authentication and quota errors as actionable blockers. Retry rate limits and transient errors only within bounded limits; prevent duplicate tool actions when retrying a model request. |
| Playwright | Browser automation is a test capability, not a privileged external integration. Use dedicated least-privilege test identities for authenticated flows and keep credentials in CI secrets. | Test owner approves target environment and account. Restrict production credentials and destructive actions; default to non-production environments. | Test run, environment, commit SHA, scenario/tag, result, and trace/artifact reference with secrets and personal data redacted. | Fail visibly on missing browser, credentials, or environment. Retry only known transient infrastructure failures; never convert a failed assertion into success. |
| CI/CD and deployment | GitHub Actions permissions default to read-only. Prefer OIDC federation for cloud deployment credentials over long-lived cloud keys. Separate preview and production deployment roles. | Repository and cloud owners configure trust conditions, environment protection, and required human approval for production. Confirm destination and commit SHA before deploy. | Workflow/run ID, actor, commit SHA, environment, approval, artifact digest, deployment result, and rollback reference. | Cancel stale runs where safe. Use bounded retries for transient infrastructure errors. On failed/partial deployment, report the state and invoke a documented rollback or require operator action; never claim success without provider confirmation. |

## Cross-integration requirements

- Store credentials in a managed secret store, scope them to a project or installation, rotate them, and provide revocation instructions.
- Use OAuth `state` and exact registered redirect URIs for browser authorization flows. Keep access/refresh tokens out of the browser and redact authorization headers.
- Record append-only audit events for externally visible reads and writes. Include actor, target, operation, correlation ID, timestamp, and provider result while minimizing personal or customer data.
- Distinguish permission errors, validation errors, rate limits, transient outages, and ambiguous timeouts. Never silently fall back to seeded data or fabricated success.
- Define idempotency, bounded retry, reconciliation, and recovery behavior for each write before enabling it.
- Verify integration tests against a dedicated real test tenant/repository when available. Tests must clearly identify when credentials or an external service are unavailable; they must not substitute a mock and label it end-to-end coverage.
- Require a human confirmation comment in Jira before an AI task starts, and re-check the issue, comment author, task revision, and approval timestamp immediately before execution.
